## Thresholds

Projection thresholds are copied from `soma_retargeter.robotics.v3.profile._projection_quality_threshold`:

- Neutral motion normalized residual: `0.001`
- Hand position normalized residual, `rho_p`: `0.12`
- Foot position normalized residual, `rho_p`: `0.06`
- Torso rotation normalized residual, `rho_R`: `0.08`
- Default normalized residual: `0.05`

Numerical stability thresholds are copied from
`soma_retargeter.robotics.v3.reachability.analyze_reachability`:

- `stable_sample_fraction >= 0.95`
- `engine_available_rate >= 1.0`
- `relevant_rank_agreement_rate >= 0.95`
- `projector_distance_p95 <= 0.05`
- `engine_fd_normalized_error_p95 <= 0.02`

No threshold is lowered for the baseline ledger, and no failure is renamed into a pass.

## Ledger Evidence

Every failure row records:

- `robot_id`, `motion`, `task`, `metric_type`, original failure message, and source report hash.
- Exact threshold object and actual residual or numerical gate values.
- Active coordinates and active joint limits from the runtime adapter.
- Engine Jacobian source, backend, finiteness, dtype, convention, and translation cross-check evidence.
- Rank summary fields where available, including rank agreement, projector distance, engine/FD ranks, and numerical gate paths.
- Solver status/message. Numerical stability rows mark the solver as not applicable and include the neutral projection reference status/message.
- Semantic source/hash, semantic map model source hash, and task-specific reference/target semantic evidence.
- Chain length evidence and target distance or target angle.

The ledger is an oracle for the Step 2.3 baseline only. Future capability fixes should reduce these rows by changing solver/capability behavior and regenerating evidence, not by editing this baseline into passes.
