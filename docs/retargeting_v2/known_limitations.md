# Retargeting v2 Known Limitations

- Runtime benchmark artifacts now include separated bounded multi-motion legacy/v2 rollouts, runtime breakdowns, per-axis tracking diagnostics, morphology-projected reachable-position RMSE, and profile-task residual summaries when BVH motions and semantic site trajectories are available. Tracking and profile residual metrics now align target frames with emitted output frames after initialization/stabilization removal, but uncapped full-length comparison and solver-native residual extraction beyond those summaries are not implemented yet.
- Benchmark gates are currently report-only unless `--strict-gates` is supplied; the current bounded sample intentionally records failing RPO and synthetic-E3 gates instead of hiding known regressions. Generic Unitree G1 passes the current bounded gate set.
- Bounded benchmark windows now select the highest-motion contiguous source segment instead of the static clip prefix. The priority guard now protects hard joint-limit penetration instead of soft margin proximity, so RPO v2, generic Unitree G1 v2, and synthetic E3 v2 no longer roll back to static output in the bounded sample. Compiled-profile runtime now uses morphology-scheduled IK iteration defaults plus a range-normalized actuated joint motion limiter, so actuated velocity/acceleration gates pass in the bounded sample; RPO hand/foot tracking, synthetic E3 hand tracking, and runtime-overhead gates still fail.
- Profile validation now covers numeric health gates and left/right chain length mismatch thresholds, but true symmetry tying is still compile-time reporting rather than a separate constrained optimizer.
- Self-collision runtime barriers are optional and disabled by default through `collision_weight=0.0`; motion-level evidence is still needed before making them a default feasibility term.
- Registry coverage artifacts now make missing target coverage explicit: `e3_v2` is registered to a checked-in synthetic capability fixture until licensed E3 assets are available, while `oli` is not registered in the current workspace and keeps a structured onboarding report.
- Generic Unitree G1 now compiles against Newton's built-in 29DoF MJCF fallback when no local XML is registered. The named `unitree_g1_23dof` coverage target uses Newton's built-in 23DoF MJCF fallback and a separate generated profile; `unitree_g1_29dof` resolves to the generic 29DoF fallback.
- Semantic auto-detection now fills missing entries with conservative body-name matching, but topology and rest-pose spatial inference are still shallow; explicit `ik_map` remains the most reliable path.
- Virtual hand and foot sites now prefer explicit MJCF sites, distal child anchors, and then primitive geom or STL mesh distal bounds when available, but non-STL mesh formats and rotated/fromto geom bounds are still limited.
- Position IK now uses compiled semantic-site offsets when the site is reachable enough to be a runtime target. RPO hand offsets are still treated as reporting sites rather than IK target offsets because the current RPO profile maps hands to elbow links without wrist-supported reach.
- The bounded RPO hand tracking failure improves substantially when single-axis projected torso rotation is treated as a weak style target and low-rank no-wrist endpoint weights are softened, but it still fails the report-only gate. The reachable-position diagnostics show this is not only an unreachable-axis artifact: RPO v2 records reachable hand/foot RMSE around `0.25/0.35` versus legacy `0.18/0.12`.
- Task weights now come from compiler `normalized_weight` values, with a morphology schedule that weakens single-axis projected torso tracking, softens low-rank no-wrist hand position tasks across torso profiles, softens single-axis foot position tasks, softens multi-axis projected torso rotation, and strengthens foot position tasks for multi-axis torso robots. A rank-guarded tangent pole schedule now enables analytic pole-vector residuals only for multi-axis torso profiles with rank-2 hand reach, making the bounded Unitree G1 default path pass without robot-name branches. The schedule is still validated only on the current bounded sample and does not yet pass RPO hand/foot or E3 hand gates.
- Root/ground metadata uses compile-time semantic hips and virtual foot site rest positions only; runtime root-height stabilization still needs motion-level acceptance metrics.
- The priority residual guard currently protects hard joint-limit penetration after runtime clamping, not all high-priority feasibility residuals.
- Synthetic E3 v2 validates the minimal-map compile/runtime path, but its checked-in MJCF is a capability fixture, not a vendor robot asset. It currently passes bounded foot/root/torso/smoothness gates after virtual sole anchor offsets are merged into both legacy and v2 runtime configs and low-rank no-wrist hand tasks are softened, but still fails full hand tracking (`1.20` versus legacy `0.59`) plus runtime. Its hand chains have translational reach rank `0`, so both legacy and v2 reachable hand RMSE are `0.0`; the full hand metric is documenting unreachable style error rather than reachable-axis tracking error.
- Contact heuristic inference now accepts both Warp transforms and numpy transform rows. This removes the synthetic E3 contact-lock fallback warning seen in earlier artifacts, but contact-quality acceptance still needs motions with reliable explicit contact labels.
- The current runtime overhead is solver dominated in bounded artifacts: v2 target setup is small relative to solve time. Single-axis torso profiles now use a lower 4-iteration default, with RPO v2 still in mixed Jacobian mode around `40` solve FPS. Generic Unitree G1 now reaches pure analytic sparse objectives through the rank-guarded tangent pole schedule and passes the runtime gate on the bounded sample. Synthetic E3 v2 remains mixed because pole-vector tasks stay autodiff and still fails runtime.
- Analytic direction-objective Jacobians are enabled only for multi-axis torso profiles. Single-axis torso profiles keep the autodiff direction objective until the analytic path is validated without regressing bounded RPO hand/foot tracking. Pole-vector objectives have an experimental analytic Jacobian implementation with expanded finite-difference coverage. Runtime configs enable the two-row tangent analytic pole residual only when morphology indicates multi-axis torso rotation and rank-2 hand reach; generic Unitree G1 takes this path, while RPO and synthetic E3 keep autodiff pole tasks. The broader `v2_pole_tangent_analytic` diagnostic still exists, but unconditional activation is not safe as a default because it regresses RPO tracking and can introduce synthetic-E3 safety/root gate failures.
- Generic Unitree G1 hand/foot tracking, root tilt, smoothness, penetration, and runtime now pass in the bounded artifacts after semantic-site offset tracking, morphology-scheduled task weights, and rank-guarded tangent pole scheduling.
