# Retargeting v2 Known Limitations

- Runtime benchmark artifacts now include separated bounded multi-motion legacy/v2 rollouts, runtime breakdowns, per-axis tracking diagnostics, and profile-task residual summaries when BVH motions and semantic site trajectories are available. Tracking and profile residual metrics now align target frames with emitted output frames after initialization/stabilization removal, but uncapped full-length comparison and solver-native residual extraction beyond those summaries are not implemented yet.
- Benchmark gates are currently report-only unless `--strict-gates` is supplied; the current bounded sample intentionally records failing gates instead of hiding known RPO/Unitree/synthetic-E3 regressions.
- Bounded benchmark windows now select the highest-motion contiguous source segment instead of the static clip prefix. The priority guard now protects hard joint-limit penetration instead of soft margin proximity, so RPO v2, generic Unitree G1 v2, and synthetic E3 v2 no longer roll back to static output in the bounded sample. Compiled-profile runtime now uses morphology-scheduled IK iteration defaults plus a range-normalized actuated joint motion limiter, so actuated velocity/acceleration gates pass in the bounded sample; RPO hand/foot tracking, synthetic E3 hand tracking, and runtime-overhead gates still fail.
- Profile validation now covers numeric health gates and left/right chain length mismatch thresholds, but true symmetry tying is still compile-time reporting rather than a separate constrained optimizer.
- Self-collision runtime barriers are optional and disabled by default through `collision_weight=0.0`; motion-level evidence is still needed before making them a default feasibility term.
- Registry coverage artifacts now make missing target coverage explicit: `e3_v2` is registered to a checked-in synthetic capability fixture until licensed E3 assets are available, while `oli` is not registered in the current workspace and keeps a structured onboarding report.
- Generic Unitree G1 now compiles against Newton's built-in 29DoF MJCF fallback when no local XML is registered. The named `unitree_g1_23dof` coverage target uses Newton's built-in 23DoF MJCF fallback and a separate generated profile; `unitree_g1_29dof` resolves to the generic 29DoF fallback.
- Semantic auto-detection now fills missing entries with conservative body-name matching, but topology and rest-pose spatial inference are still shallow; explicit `ik_map` remains the most reliable path.
- Virtual hand and foot sites now prefer explicit MJCF sites, distal child anchors, and then primitive geom or STL mesh distal bounds when available, but non-STL mesh formats and rotated/fromto geom bounds are still limited.
- Position IK now uses compiled semantic-site offsets when the site is reachable enough to be a runtime target. RPO hand offsets are still treated as reporting sites rather than IK target offsets because the current RPO profile maps hands to elbow links without wrist-supported reach.
- The bounded RPO hand tracking failure improves substantially when single-axis projected torso rotation is treated as a weak style target and low-rank no-wrist endpoint weights are softened, but it still fails the report-only gate: current v2 hand `axis_rmse` is approximately `[0.21, 0.21, 0.23]` with `mean_error` `[-0.10, -0.06, -0.03]`. RPO foot residuals remain elevated at approximately `[0.18, 0.24, 0.22]`.
- Task weights now come from compiler `normalized_weight` values, with a morphology schedule that weakens single-axis projected torso tracking, softens low-rank single-axis endpoint position tasks, softens multi-axis projected torso rotation, and strengthens foot position tasks for multi-axis torso robots. This resolves the bounded Unitree G1 root-tilt regression and improves RPO tracking without robot-name branches, but the schedule is still validated only on the current bounded RPO/Unitree sample and does not yet pass RPO hand/foot gates.
- Root/ground metadata uses compile-time semantic hips and virtual foot site rest positions only; runtime root-height stabilization still needs motion-level acceptance metrics.
- The priority residual guard currently protects hard joint-limit penetration after runtime clamping, not all high-priority feasibility residuals.
- Synthetic E3 v2 validates the minimal-map compile/runtime path, but its checked-in MJCF is a capability fixture, not a vendor robot asset. It currently passes bounded foot/root/torso/smoothness gates and fails hand tracking (`1.20` versus legacy `0.59`) plus runtime.
- The current runtime overhead is solver dominated in bounded artifacts: v2 target setup is small relative to solve time. Single-axis torso profiles now use a lower 4-iteration default, with RPO v2 solve FPS roughly `40.2` versus legacy `162.1`. Multi-axis torso profiles keep 8 iterations to preserve Unitree tracking, and analytic direction-objective Jacobians keep Unitree v2 solve FPS roughly `36.1` versus legacy `165.6`; synthetic E3 v2 records roughly `44.5` versus legacy `243.0`. All three benchmarked robots still fail the report-only runtime-overhead gates.
- Analytic direction-objective Jacobians are enabled only for multi-axis torso profiles. Single-axis torso profiles keep the autodiff direction objective until the analytic path is validated without regressing bounded RPO hand/foot tracking. Pole-vector objectives have an experimental analytic Jacobian implementation with expanded finite-difference coverage, but runtime configs keep it disabled because direct enablement lowers runtime while regressing bounded RPO and Unitree tracking/root gates. The benchmark now includes an optional `v2_pole_analytic` diagnostic compare mode; it shows Unitree can reach pure analytic Jacobian mode and roughly `206.9` solve FPS, but with hand/foot RMSE regressing to `0.80/0.58`, so it is not safe as a default. Runtime now selects pure analytic Jacobian mode when every active objective supports analytic Jacobians; current default v2 artifacts still run in mixed mode because pole-vector tasks remain autodiff.
- Generic Unitree G1 hand/foot tracking and root tilt now pass in the bounded artifacts after semantic-site offset tracking and morphology-scheduled task weights, but runtime remains well above the report-only gate.
