# Retargeting v2 Known Limitations

- Runtime benchmark artifacts now include separated bounded multi-motion legacy/v2 rollouts, runtime breakdowns, per-axis tracking diagnostics, and profile-task residual summaries when BVH motions and semantic site trajectories are available. Tracking and profile residual metrics now align target frames with emitted output frames after initialization/stabilization removal, but uncapped full-length comparison and solver-native residual extraction beyond those summaries are not implemented yet.
- Benchmark gates are currently report-only unless `--strict-gates` is supplied; the current bounded sample intentionally records failing gates instead of hiding known RPO/Unitree regressions.
- Bounded benchmark windows now select the highest-motion contiguous source segment instead of the static clip prefix. The priority guard now protects hard joint-limit penetration instead of soft margin proximity, so RPO v2 and generic Unitree G1 v2 no longer roll back to static output in the bounded sample. Compiled-profile runtime now uses morphology-scheduled IK iteration defaults plus a range-normalized actuated joint motion limiter, so actuated velocity/acceleration gates pass in the bounded sample; RPO hand/foot tracking and both robots' runtime-overhead gates still fail.
- Profile validation now covers numeric health gates and left/right chain length mismatch thresholds, but true symmetry tying is still compile-time reporting rather than a separate constrained optimizer.
- Self-collision runtime barriers are optional and disabled by default through `collision_weight=0.0`; motion-level evidence is still needed before making them a default feasibility term.
- Registry coverage artifacts now make missing target coverage explicit: `e3_v2` and `oli` are not registered in the current workspace, so runtime benchmark artifacts cover `roboparty_rpo` and generic `unitree_g1` by default.
- Generic Unitree G1 now compiles against Newton's built-in 29DoF MJCF fallback when no local XML is registered. The named `unitree_g1_23dof` coverage target uses Newton's built-in 23DoF MJCF fallback and a separate generated profile; `unitree_g1_29dof` resolves to the generic 29DoF fallback.
- Semantic auto-detection now fills missing entries with conservative body-name matching, but topology and rest-pose spatial inference are still shallow; explicit `ik_map` remains the most reliable path.
- Virtual hand and foot sites now prefer explicit MJCF sites, distal child anchors, and then primitive geom or STL mesh distal bounds when available, but non-STL mesh formats and rotated/fromto geom bounds are still limited.
- Position IK now uses compiled semantic-site offsets when the site is reachable enough to be a runtime target. RPO hand offsets are still treated as reporting sites rather than IK target offsets because the current RPO profile maps hands to elbow links without wrist-supported reach.
- The bounded RPO hand tracking failure improves substantially when single-axis projected torso rotation is treated as a weak style target, but it still fails the report-only gate: current v2 hand `axis_rmse` is approximately `[0.21, 0.21, 0.24]` with `mean_error` `[-0.10, -0.06, -0.03]`. RPO foot residuals remain elevated, especially y/z, at approximately `[0.18, 0.26, 0.25]`.
- Task weights now come from compiler `normalized_weight` values, with a morphology schedule that weakens single-axis projected torso tracking, softens multi-axis projected torso rotation, and strengthens foot position tasks for multi-axis torso robots. This resolves the bounded Unitree G1 root-tilt regression and improves RPO tracking without robot-name branches, but the schedule is still validated only on the current bounded RPO/Unitree sample and does not yet pass RPO hand/foot gates.
- Root/ground metadata uses compile-time semantic hips and virtual foot site rest positions only; runtime root-height stabilization still needs motion-level acceptance metrics.
- The priority residual guard currently protects hard joint-limit penetration after runtime clamping, not all high-priority feasibility residuals.
- The current runtime overhead is solver dominated in bounded artifacts: v2 target setup is small relative to solve time. Single-axis torso profiles now use a lower 4-iteration default, improving RPO solve FPS to roughly `40.8` versus legacy `190.5`. Multi-axis torso profiles keep 8 iterations to preserve Unitree tracking, and analytic direction-objective Jacobians improve Unitree solve FPS to roughly `36.3` versus legacy `169.0`; both robots still fail the report-only runtime-overhead gates.
- Analytic direction-objective Jacobians are enabled only for multi-axis torso profiles. Single-axis torso profiles keep the autodiff direction objective until the analytic path is validated without regressing bounded RPO hand/foot tracking. Pole-vector objectives have an experimental analytic Jacobian implementation, but runtime configs keep it disabled because direct enablement lowered runtime while regressing bounded RPO and Unitree tracking/root gates.
- Generic Unitree G1 hand/foot tracking and root tilt now pass in the bounded artifacts after semantic-site offset tracking and morphology-scheduled task weights, but runtime remains well above the report-only gate.
